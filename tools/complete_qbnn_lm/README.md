# 完全QBNN 文字言語モデル（学習・評価・ブラウザ実行）

FFN のニューロンを完全ブロッホ球にした文字単位の GPT を、日本語の文章・会話・コードで学習するためのスクリプト群。
学習したモデルはブラウザ用に書き出し、`browser/` のチャット画面（観測室）で動かせる。CPU だけで動く。

## 構成

| ファイル | 役割 |
|---|---|
| `scale_exp.py` | モデル本体（`GPT`、FFN の種類 `gelu` / `tanh` / `complete` / `nq` / `rnn`、時間方向を RWKV-7 にした `rwkv7a` / `rwkv7` / `rwkv7b` / `rwkv7c` / `rwkv7d` / `rwkv7e`、大きさ `XS`〜`XL`）と、同じ条件でニューロンの種類を比べる実験 |
| `infer_rnn.py`, `rounds.sh` | 時間方向の扱いが違うモデルを同じ検証データ・同じプロンプトで比べる／全モデルを区切りごとに続けて学習して比べる |
| `apqb_gamma.py` | APQB 由来の鍵・更新率（`rwkv7c` / `rwkv7d` / `rwkv7e`）の γ、元の値に対する大きさ、γ を 0 にしたときの損失の変化 |
| `infer_rnn.py` | 種類の違うモデルを、同じ検証データ・同じプロンプト・同じ乱数で比べる（`rnn` は再帰を切ったときの損失も出す） |
| `chat_data.py` | 会話データ（oasst 形式 `{"conversations": [{"from", "value"}]}`）を `<bos>ユーザー<sep>応答<eos>` の列にする |
| `sft.py`, `sft_chat.py` | 指示・会話データでの追加学習（初期の M モデル用） |
| `cont.py` | 文章（損失は全文字）と会話・指示（損失は応答と `<eos>` だけ）を半々に混ぜた学習。300 ステップごとに保存し、再実行で続きから再開する |
| `cont2.py` | `cont.py` に青空文庫・Wikipedia 話題の多段会話・llm-japanese-dataset を加えたもの |
| `cont3.py` | `cont2.py` に Magpie-Tanuki・Nemotron 会話・hh-rlhf 日本語・JaQuAD・Wikinews を加えたもの |
| `prep_new.py`, `prep_llmjp.py`, `prep_new2.py` | 上の追加データを、語彙内の文字だけ・文脈 256 文字に収まるものに絞って保存する |
| `eval_iq.py` | 「賢さ」テスト。選択肢ごとの尤度で答えを選ばせる（JCommonsenseQA・首都・県庁所在地・足し算・助詞） |
| `eval_metrics.py` | 損失以外の指標（top-k 正解率・較正誤差・生成の多様性など） |
| `infer_xl3.py` | 2 つのモデルに同じ質問・同じ乱数で答えさせて比べる |
| `export_gpt.py` | 学習済みモデルを fp16 にしてブラウザ用に書き出す（`meta_gpt.json`、12 MB ごとの `weights_k.wasm`、PyTorch の参照出力 `ref_gpt.json`） |
| `browser/engine_gpt.js` | ブラウザ・Node.js 用の推論エンジン（KV キャッシュ、文脈が満ちたら半分を残してずらす） |
| `browser/template_chat_bin.html`, `browser/build_gpt_bin.py` | チャット画面（観測室）。生成中の完全ブロッホ球ニューロンの状態を表示する |
| `browser/test_gpt.js` | エンジンの出力が PyTorch と一致するかを確かめる |

## データの置き場所

学習データとモデルは環境変数 `QBNN_LM_DATA` のディレクトリに置く（既定は `tools/complete_qbnn_lm/data/`）。
`prep_*.py` が読む Hugging Face のダウンロードは `QBNN_LM_DOWNLOADS`（既定は `$QBNN_LM_DATA/downloads`）。

使ったファイルは次のとおり。

- 文章: `jawiki*.txt`（日本語版 Wikipedia）、`fineweb_train.txt` / `fineweb_val.txt`（FineWeb-2 日本語）、`aozora.txt` / `news_aozora.txt`（青空文庫・Wikinews）、`code.txt`（Python）
- 会話: `oasst1-chat-44k-ja.json`、`oasst2-chat-68k-ja.json`、`conv_wiki.json`、`chat_new3.json`
- 指示: `instruct_raw.json`（dolly-ja・amenokaku-code・japanese_alpaca）、`llmjp_mix.json`、`instr_new3.json`、`jaquad_val.json`
- 語彙: `vocab.json`（Wikipedia で多い 4,000 文字）、`sft_meta.json`（語彙に `<bos>` `<sep>` `<eos>` `<pad>` を足したもの）

## 使い方

```bash
export QBNN_LM_DATA=/path/to/data

# ニューロンの種類の比較（M, 6000 ステップ）
python scale_exp.py M complete 6000 0 4

# 文章＋会話の学習: STEPS INIT LM_ROWS CHAT_ROWS LR TAG 文章ファイル SIZE WARMUP
python cont3.py 40000 model_M_complete_cont_XL260000.pt 10 6 2e-4 _XL3 fineweb_train.txt+jawiki3.txt XL 300

# 賢さテスト（:sft は特殊トークン入りの語彙と文脈 256）
python eval_iq.py "XL=XL:complete:model_M_complete_cont_XL340000.pt:sft"

# ブラウザ用に書き出して観測室を組み立てる
python export_gpt.py $QBNN_LM_DATA/model_M_complete_cont_XL340000.pt XL out $QBNN_LM_DATA/sft_meta.json
cp browser/* out/ && cd out
node test_gpt.js                                  # PyTorch との一致を確認
python build_gpt_bin.py . "学習データの説明" "2,740万"   # observatory_L.html ができる
```

`observatory_L.html` は同じディレクトリの `weights_0.wasm` … を読み込む。中身は fp16 の重みで、配信先が `.bin` を扱えないので拡張子を `.wasm` にしている。

## 結果（CPU 4 コア）

**ニューロンの種類の比較**（M = 幅 256・4 層、約 420 万パラメータ、6,000 ステップ、Wikipedia の検証損失、bits/文字）

| FFN のニューロン | 損失 |
|---|---|
| GELU | 4.186 |
| 完全ブロッホ球 | 4.200 |
| NeuroQuantum 型 QBNN | 4.347 |

パラメータ数をそろえると、完全ブロッホ球は GELU とほぼ同じで、NeuroQuantum 型より良い。

**大きさと学習量**（文脈 256、bits/文字、低いほど良い）

| モデル | パラメータ | 学習 | Web | Wikipedia | コード | 会話 | 指示 |
|---|---|---|---|---|---|---|---|
| L | 1,229 万 | 計 11 万ステップ | 3.809 | 3.376 | 1.379 | 2.726 | 2.451 |
| XL | 2,740 万 | 4 万ステップ | 3.979 | 3.566 | 1.518 | 2.897 | 2.666 |
| XL | 2,740 万 | 計 10 万ステップ | 3.748 | 3.328 | 1.394 | 2.667 | 2.412 |
| XL | 2,740 万 | 計 14 万ステップ（`cont3.py` のデータを追加） | **3.668** | **3.262** | **1.356** | **2.618** | **2.336** |

XL は 4 万ステップでは L に負けたが、大きさに見合う量（10 万ステップ）を学習させると全体で L を上回った。

**賢さテスト**（選択肢から尤度で選ぶ。偶然に当たる率は JCommonsenseQA・首都・県庁所在地 20%、足し算 5%、助詞 14%）

| モデル | JCommonsenseQA | 首都 | 県庁所在地 | 足し算 | 助詞 |
|---|---|---|---|---|---|
| L 計 11 万 | 25.0% | 20.0% | 38.3% | 4% | 77.2% |
| XL 計 10 万 | 27.3% | 22.5% | 61.7% | 8% | 78.5% |
| XL 計 14 万 | 26.5% | 22.5% | **66.0%** | 8% | **79.2%** |

クイズデータ（llm-japanese-dataset）には首都・県庁所在地を問う問題が含まれうるので、その 2 つの点には似た問題を学習で見た効果が混ざっている可能性がある。

**推論の例**（XL 計 14 万）

- 「日本の首都はどこですか？」→「日本の首都は東京です。」（乱数によっては誤る）
- 「こんにちは！」→「こんにちは！私はオープンアシスタントです。何かお手伝いしましょうか？」
- 「おすすめの勉強方法を教えてください。」→「もちろんです！以下におすすめの勉強方法を紹介します。…」

文体・答え方の形はよく覚えるが、個々の事実（富士山・作家など）はまだ誤りが多く、会話の 2 往復目以降は話の筋を保てないことが多い。

**ブラウザ実行**: `test_gpt.js` で次の文字の対数確率の差は最大 6.8×10⁻⁴、200 文字の貪欲生成は PyTorch と同じ。XL で 1 文字あたり約 53 ms。

## 時間方向の扱いの比較（RNN・RWKV-7）

S（幅 128・4 層・4 ヘッド）、1,500 ステップ（1 ステップ 32 行 × 128 文字）、シード 0、同じデータ順。
データは日本語版 Wikipedia（`wikimedia/wikipedia` 20231101.ja の最後のシャードの先頭 6,000 万文字、最後の 100 万文字を検証用）。
損失は検証 200 バッチの bits/文字（低いほど良い）。CPU 4 コアで、RWKV-7 の 3 本（A・C・D）は 1 スレッドずつ並べて学習した。

| 種類 | 時間方向 | FFN | パラメータ | 損失 | 学習時間 |
|---|---|---|---|---|---|
| `complete` | Attention | 完全ブロッホ球 | 132 万 | 6.028 | 13 分 |
| `rnn` | Attention | 完全ブロッホ球の状態 b_{t-1} を次の時刻へ渡す | 132 万 | 6.012 | 28 分 |
| A `rwkv7a` | RWKV-7 | ReLU²（標準の channel mixing） | 137 万 | 5.645 | 83 分 |
| B `rwkv7` | RWKV-7 | 完全ブロッホ球 | 138 万 | **5.519** | 58 分 |
| C `rwkv7c` | RWKV-7、鍵に γ_k W_B b を足す | 完全ブロッホ球 | 143 万 | 5.607 | 92 分 |
| D `rwkv7d` | C ＋ 更新率 a の sigmoid の前に γ_a W_A b を足す | 完全ブロッホ球 | 145 万 | 5.559 | 91 分 |
| `rwkv7b` | RWKV-7、受容 r と鍵 k をブロッホ球ニューロンの出力に置き換え | 完全ブロッホ球 | 137 万 | 5.579 | 61 分 |

- FFN を完全ブロッホ球にすると、標準の RWKV-7 より 0.126 良かった（A → B）。300〜1,500 ステップのどの評価でも順位は B < D < C < A で変わらなかった。
- APQB 由来の鍵（B → C）は 0.088 悪く、更新率を加える（C → D）と 0.048 良くなったが、B には届かなかった（シード 0 だけの結果。シードを変えると逆転する。下の「シードを変えた確認」）。
- `rnn` は再帰の重みをゼロにすると損失が 18.3 になり、ブロッホ球の状態を記憶として強く使っている。ただし `complete` との差（0.016）はシード 1 本のばらつきの範囲である。
- RWKV-7 は 1 文字ずつ順に計算しているので（チャンク並列なし、v-first の残差なし）、同じステップ数で Attention 版より 4〜7 倍遅い。
- 小さいモデルの短い学習で、シードも 1 本だけなので、0.1 未満の差は確かめ直しが要る。生成文は 7 本とも Wikipedia の書式（年号・脚注・カテゴリ）をまねるだけで、質の差は読み取れなかった。

```bash
python scale_exp.py S rwkv7 1500 0 2
python infer_rnn.py S 1500 complete,rnn,rwkv7a,rwkv7,rwkv7c,rwkv7d,rwkv7b
```

### 続けて 3,000 ステップまで（`rounds.sh`）

1,500 ステップの重みから、学習率の山を最大値半分で張り直して 1,500 ステップ続けた（シード 0、検証 200 バッチ）。
`rwkv7e`（B ＋ APQB 由来の更新率だけ）はこの区切りで 0 → 1,500 を学習した。

| 種類 | 1,500 ステップ | 3,000 ステップ | B との差（3,000） |
|---|---|---|---|
| `complete` | 6.028 | 5.635 | +0.472 |
| `rnn` | 6.012 | 5.595 | +0.432 |
| A `rwkv7a` | 5.645 | 5.277 | +0.114 |
| **B `rwkv7`** | **5.519** | **5.163** | — |
| C `rwkv7c` | 5.607 | 5.226 | +0.063 |
| D `rwkv7d` | 5.559 | 5.194 | +0.031 |
| `rwkv7e` | 5.606 | （学習中） | — |
| `rwkv7b` | 5.579 | 5.211 | +0.048 |

- 3,000 ステップでも B が最も良く、A との差は 0.114 とほぼ保たれた。RWKV-7 系の順位は B < D < `rwkv7b` < C < A。
- APQB を足した C・D と B との差は 0.088 → 0.063、0.040 → 0.031 と少し縮んだが、B を上回ってはいない（シード 0 だけ。1,500 ステップでは 3 シードで見ると B・C・D の差はばらつきの範囲だった）。
- `rwkv7e`（更新率だけ）は 1,500 ステップで 5.606 と、鍵だけの C（5.607）と同じくらいで、両方を足した D（5.559）より悪かった。
- `rnn` は再帰を切ると 17.5 bits/文字になり、記憶を使い続けている。`complete` との差は 0.04 に広がった。
- 学習した γ（シード 0、1,500 ステップ、層 0〜3）: C の γ_k = [−0.425, 0.466, 0.122, 0.000]、D の γ_k = [0.375, 0.546, 0.247, 0.000]、γ_a = [0.448, 0.639, −0.355, −0.002]。
  前の 3 層では APQB の項が使われ、最後の層だけ γ がほぼ 0 のまま残った（初期化直後の最後の層の勾配はほかの層と同じくらいあるので、学習の結果）。
  鍵 k に対する APQB の項の大きさと、γ を 0 にしたときの損失の変化は `apqb_gamma.py` で測れる。
- シード 1・2 での 3,000 ステップの確認は下の「シードを変えた確認（3,000 ステップ）」。

```bash
bash rounds.sh 6000 1500 4                          # 全モデルを 1,500 ステップずつ続けて学習し、区切りごとに round_<n>.txt
python apqb_gamma.py S $QBNN_LM_DATA/model_S_rwkv7c_1500.pt $QBNN_LM_DATA/model_S_rwkv7d_1500.pt
```

### シードを変えた確認（1,500 ステップ）

A〜D をシード 1・2 でも 0 → 1,500 ステップ学習した（データ・設定はシード 0 と同じ、検証 200 バッチ）。

| 種類 | シード 0 | シード 1 | シード 2 | 平均 | 標準偏差 |
|---|---|---|---|---|---|
| A `rwkv7a`（標準） | 5.645 | 5.670 | 5.670 | 5.662 | 0.015 |
| B `rwkv7`（完全ブロッホ球 FFN） | **5.519** | **5.556** | 5.631 | **5.569** | 0.057 |
| C `rwkv7c`（＋APQB 鍵） | 5.607 | 5.575 | **5.570** | 5.584 | 0.020 |
| D `rwkv7d`（＋鍵・更新率） | 5.559 | 5.612 | 5.613 | 5.595 | 0.031 |

| 差（同じシードどうし） | シード 0 | シード 1 | シード 2 | 平均 |
|---|---|---|---|---|
| A − B | +0.126 | +0.115 | +0.039 | +0.093 |
| C − B | +0.088 | +0.020 | −0.062 | +0.015 |
| D − B | +0.040 | +0.057 | −0.018 | +0.026 |

- 完全ブロッホ球 FFN（B・C・D）は 3 シードすべてで標準 RWKV-7（A）より良かった。差は 0.04〜0.13 とシードで幅がある。
- APQB を足した C・D と B の順位はシードで入れ替わる（シード 2 では C が最も良い）。平均の差（0.015、0.026）はシード間のばらつき（B の標準偏差 0.057）より小さく、
  この規模・この学習量では APQB の鍵・更新率は良くも悪くもしていない、というのが今の結論。C と D の順もシードで入れ替わる。

### APQB の γ（1,500 ステップ）

`apqb_gamma.py` の結果。比は検証データでの RMS の比（APQB の項 ÷ 元の値）、損失の変化は全層の γ を 0 にしたとき（検証 100 バッチ）。

| | 層 0 | 層 1 | 層 2 | 層 3 | γ=0 で切ったとき |
|---|---|---|---|---|---|
| C シード 1: γ_k（比） | −0.374（19%） | +0.530（26%） | −0.278（10%） | +0.005（0.2%） | +0.026 |
| C シード 2: γ_k（比） | +0.495（22%） | −0.401（29%） | −0.262（8%） | +0.001（0.02%） | +0.030 |
| D シード 1: γ_k（比） | −0.501（28%） | +0.377（30%） | +0.081（2%） | +0.004（0.05%） | +0.039 |
| D シード 1: γ_a（比） | −0.564（35%） | −0.600（23%） | −0.226（14%） | +0.001（0.07%） | （γ_k と同時に切る） |
| D シード 2: γ_k（比） | +0.485（19%） | +0.415（23%） | +0.180（7%） | −0.005（0.1%） | +0.023 |
| D シード 2: γ_a（比） | −0.570（18%） | +0.573（21%） | +0.195（10%） | −0.050（3%） | （同上） |

- 層 0・1 では APQB の項が元の鍵・更新率の 2〜3 割の大きさになり、実際に使われている。切ると損失が 0.02〜0.04 悪くなる。
- 最後の層（層 3）の γ はシード 0〜2 のどれでもほぼ 0 のままで、そこでは使われない。
- γ の符号はシードごとにばらばらで、決まった役割（位相で鍵を回す、など）を学んでいるようには見えない。ほかの入力と同じ「追加の特徴」として使われている。
- 切ったときの悪化（0.02〜0.04）は、最初から APQB なしで学習した B とのシード間の差より小さい。

### シードを変えた確認（3,000 ステップ）

シード 1・2 の A〜D も 1,500 ステップの重みから 3,000 ステップまで続けた（続け方はシード 0 と同じ、検証 200 バッチ）。

| D `rwkv7d`（＋鍵・更新率） | 5.194 | 5.245 | 5.243 | 5.227 | 0.029 |

| D シード 1: γ_a（比） | −0.753（47%） | −0.866（35%） | −0.485（25%） | +0.050（2%） | （γ_k と同時に切る） |
| D シード 2: γ_k（比） | +0.622（27%） | +0.580（35%） | +0.388（20%） | −0.017（0.4%） | +0.061 |
| D シード 2: γ_a（比） | −0.755（21%） | +0.894（31%） | +0.425（20%） | −0.117（6%） | （同上） |

- 学習を続けると γ は大きくなり（1,500 → 3,000 ステップで層 0〜2 の比は 2〜3 割 → 2〜4 割）、切ったときの悪化も 0.02〜0.04 から 0.06〜0.10 に増えた。モデルは APQB の項にだんだん頼るようになっている。
- それでも最初から APQB なしで学習した B と同じくらいの損失にしかならない。APQB の項は、なくても別の経路で表せる情報を運んでいると考えられる。
- 最後の層の比は 0.2〜6% と小さいままで、少しずつ増えている。γ の符号はシードごとにばらばらなのも 1,500 ステップのときと同じ。
